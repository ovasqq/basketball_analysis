# Подсветка разметки без наложения на посторонние объекты

Сейчас `court_markings.draw_markings` рисует шаблон FIBA, спроецированный через
гомографию, **везде**: поверх мяча, игроков, теней. Ниже — как рисовать линию
только там, где она реально видна.

## Идея

Перейти от «рисовать по шаблону» к «рисовать по маске»:

```
mask = полоса_вокруг_шаблона  &  похоже_на_линию  &  ~объекты
out[mask > 0] = color          # или смешивание с alpha
```

- **полоса вокруг шаблона**: те же полилинии, что сейчас, но нарисованные в
  отдельную маску толщиной ±5–10 px. Запас покрывает неточность калибровки.
- **похоже на линию**: пиксель выглядит как разметка (см. способ 1).
- **объекты**: маски игроков, мяча и т.п. (способы 2–3).

Побочный плюс: подсветка «прилипает» к реальной линии и сама исправляет
неточность гомографии в несколько пикселей.

## Способы (по возрастанию сложности, на практике комбинируются)

### 1. Проверка пикселя на «линейность» — без новых зависимостей

На `frame.jpg` линии **тёмные и тонкие** на светлом паркете. Такие полосы
выделяет морфологический black-hat:

```python
gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
k = cv2.getStructuringElement(cv2.MORPH_RECT, (7, 7))   # больше толщины линии в px
line_like = cv2.morphologyEx(gray, cv2.MORPH_BLACKHAT, k) > 25
```

- Мяч крупный и оранжевый, поэтому black-hat его не выделит, и на нём подсветки не будет.
- Для белых линий на другой площадке нужен top-hat (`MORPH_TOPHAT`). Тип
  линии лучше хранить в калибровке, а не угадывать.
- Ядро зависит от толщины линии в пикселях, а она меняется с перспективой
  (у дальней лицевой линия тоньше). Начать с одного ядра, при проблемах
  считать ядро по масштабу гомографии в точке.
- **Слабое место:** тёмные объекты с тонкими краями (обувь, чёрная форма,
  щели паркета, тени) проходят фильтр. Отчасти спасает полоса вокруг шаблона:
  всё, что вне её, отсекается сразу.

### 2. Сегментация объектов нейросетью — основной вариант для кадров с игроками

- YOLOv8/YOLO11-seg (`ultralytics`): маски классов `person`, `sports ball`.
  Маски расширить `cv2.dilate` на несколько px (у сегментации мягкие края)
  и вычесть из маски разметки.
- SAM / SAM 2 даёт более точные контуры, но работает медленнее. Подходит для
  офлайн-обработки или как уточнение по боксам YOLO.
- Минус: видит только известные классы. Сумка, полотенце или швабра на корте
  не найдутся.

### 3. Модель фона — если это видео со статичной камеры

- Медиана по N кадрам даёт «пустую» площадку. Передний план —
  `cv2.absdiff(frame, background) > порог`, либо `cv2.createBackgroundSubtractorMOG2`.
- Ловит **любой** движущийся объект, независимо от класса.
- Минусы: неподвижный объект со временем «вливается» в фон; блики и тени
  от света дают ложные срабатывания; не годится, если камера двигается.

### 4. Проверка по профилю вдоль линии

Идти вдоль каждой полилинии шаблона и смотреть профиль яркости поперёк неё.
Есть тёмный «провал» на ожидаемом месте — линия видна; нет — перекрыта.
По сути это способ 1, но решение принимается по отрезку, а не по пикселю,
поэтому он устойчивее к шуму. Заодно даёт смещение реальной линии
относительно шаблона, то есть метрику качества калибровки.

## Рекомендуемый порядок

1. Способ 1 (black-hat + полоса) — сразу, без зависимостей.
2. При появлении кадров с игроками — способ 2 (YOLO-seg), вычитать из маски.
3. Для видео со статичной камеры — способ 3 как дополнение к 2.

## Как проверять

На текущем `frame.jpg` посторонних объектов на разметке нет, поэтому
проверить перекрытие на нём нельзя. Нужен набор из 5–10 кадров с мячом и
игроками на линиях, чтобы глазами (а лучше по размеченным маскам) смотреть
ложные срабатывания в обе стороны.
